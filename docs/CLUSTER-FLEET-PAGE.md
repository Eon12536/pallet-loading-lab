# 군집 다중 로봇 전용 페이지

`/cluster-fleet/`에서 여러 로봇 화면만 표시한다. 메인 대시보드와 기존 30개 프리셋은 보존한다. 기본은 바닥 로봇4대, 팔레트4개, 6SKU 각40개/총240개, 입고seed460000000, 1200×1000×1200mm이다. 페이지를 열면8배속으로 자동 실행한다. 로봇2~8대와 SKU당5~80개를 설정할 수 있다. 로봇 수를 변경하면 기본 공급량도 대당60개가 되도록 변경 대기한다. 적용 버튼을 누르면 실제로 초기화/재실행한다. 일시정지, 동일 입력 초기화, 다음 난수시드, 시점선택, JSON 내보내기는 기존 FlowLab 기능을 재사용한다.

기존 재현 명세와 다른 것은 공급수량이다. 30개를4팔레트에 나누면 낮게 쌓이므로 충분한 재고를 공급해 군집 적재를 시연한다. 군집의17항목 사전식 순서와 공통 경계/충돌/지지/누적하중/그리퍼/TCP 제약은 변경하지 않는다. 모든 박스를 반드시 넣거나 높이1200mm를 반드시 달성한다고 보장하지 않는다. 유효 후보가 없으면 해당 박스를 미적재로 기록하며 팔레트를 자동 반출하지 않는다. 무리한 고적재를 위해 제약을 완화하지 않는다.

시험 코드 `tests/pallet-cluster-tall.test.ts`는0.5초 공정 tick,2초 계획 주기로 공급을 끝까지 실행하고 수량 보존, 중첩/돌출/높이, 허용 회전, 지지≥0.85, 누적상부하중≤입력/1.2, 동시작업, 반출0을 검사한다. 실제 실행 원시 결과는 `cluster-fleet-tall-6-4.json`에 저장한다. 브라우저 Worker wall-clock과 다르므로 계획 계산시간/공정시간을 현장 실측으로 취급하지 않는다. 실제 관절/전체 링크 IK, 진공 밀봉, 동적 운송 안정성은 미검증이다. 중앙 구조는 로컬 Worker에서 실행하며 실제 서버 통신은 별도다.

## 이번에 실제 실행한 결과

240개 중159개 적재,81개 미적재. 높이1200/1200/1160/1200mm, 팔레트별46/40/41/32개, 최대4대 동시운반, 반출0. 2초 계획 주기 이상적 엔진 실행이며 첫seed 한 번의 결과다. Node Vitest134.49초/공정모델1872초는 현실 작업시간 보장이 아니다. 관련 회귀17개 + 신규2개 통과, 타입/배포빌드 통과. 브라우저는 Worker 지연과 배차 시점 때문에 최종 개수/높이가 달라질 수 있다. 기존30개 재현조건과240개 시연조건은 동일 실험으로 비교하지 않는다.

## 컨베이어 속도 조정
전용 시연에만 벨트210→315mm/s, 입고 예정 간격(2.6~5.2초)을1.5로 나눈1.73~3.47초를 적용한다. 정체 시 안전 간격은 우선한다. 공급수량·군집 rank·물성·안전 제약·로봇 TCP 속도는 유지한다. 기존30개 재현 프리셋은210mm/s 그대로다. 위 결과는 조정 전 측정값이며 새로운 속도의 결과로 해석하지 않는다.
검증: 12초 이송에서 입고3→4개, 이동1.5배·100mm 대기열 간격 유지; 관련11테스트와 타입·빌드 통과.


## 중앙 허브 연속 공급 (v49)
전용 시연의 메인은 뒤쪽 중앙에서 90도 방향으로 들어오며, 공통 허브에서 로봇별 독립 서브로 직접 분배한다. 기존 순차 분기·마지막 곡선 합류는 다른 페이지에서 보존한다. 물리 경로 길이로 이송하며 픽업 TCP와 팔레트 좌표는 유지한다. 속도315mm/s, 기존240개 재고를 유지하고 무작위 입고 지연을 제거한다. 안전 간격이 확보되면 다음 박스를 즉시 투입하며, 만재 대기열·불량 푸셔·배차 대기에는 상류가 정지한다. 무한 생성이나 100% 가동률 보장은 아니다.
중앙 배차는 계측 완료한 main 박스를 한 회에 최대 로봇 수만큼 살피고, 적은 이송 예약 대기열의 유효 셀로 선배차한다. 작업 중인 로봇도 다음 박스를 받을 수 있다. 서브 물리 대기열은 최대4개이며 실제 길이와 간격을 먼저 검사한다. 집기 시 다시 현재 팔레트 상태를 검증한다. 팔레트 내부 군집 rank·충돌/지지/하중/TCP 제약·9초 탐색/10초 결정 예산은 그대로다.
검증: 새로운 허브30개 실험은 전량적재(8/8/8/6), 최대4대 동시운반, 반출0. 240개 브라우저 진행에서 최대4대 동시, 54개 적재/13개 서브 대기, 수량 보존을 확인했다. 기존240개 결과는 이전 배치의 역사 기록이며 허브 최종 결과가 아니다. 허브의 원형 외접 반경+100mm로 보수적 간격을 유지한다. 이는 실제 다이버터 접촉 동역학 검증이 아니다.

## 곡선 서브 벨트 (v50)
서브 중심선과 실제 박스 경로를 같은4차 베지어 곡선으로 통일했다. 입구·픽업 끝단은 세로 접선으로 부드럽게 연결하고, 256구간 누적 길이 표와 이진 검색으로 실제315mm/s를 유지한다. 허브의 겹치는 초기 구간은 하나의 반원 분배 데크로 표시하며, 개별 서브 레일은 데크 밖에서 시작한다. 기본4대 구성의 외부 벨트 중심선 간격>1000mm, 표본 곡률반경>500mm, 이동 속도314~316mm/s를 검증했다. 팔레트·픽업 TCP·군집rank·물성·안전 검사는 변경하지 않았다.
관련15개 테스트 통과. 실제군집30개는8/8/8/6개 전량적재, 최대4대 동시운반, 반출0. 브라우저에서도4대 동시작업과 서브별 대기열/수량 보존을 확인했다. 경로는 평면 기하 모델이며 실제 곡선 벨트 기계 사양의 검증은 아니다.

## 이상 박스 예외 시연 (v51)
전용 페이지의 이상 박스 발생률 기본값은16%이며 0–100%를 입력하고 조건 적용으로 재실행할 수 있다. URL `damageRate=16`은 퍼센트 입력이다. 모서리/윗면/옆면 눌림은 기존seed+박스ID별 합성 모델로 생성된다. 발생률은 개별 확률이며 실제 수량이 정확히16%라는 뜻은 아니다. 입고 순서 난수와 분리돼 같은시드·재고·발생률은 같은형상을 재현한다.
기존 스캐너의 표면편차≥8mm 판정을 재사용한다. 판독 전에는 중앙이 불량 여부를 사용하지 않고, 판독 후에는 서브 배차·로봇 집기에서 제외한다. 메인1500mm 지점에서 푸셔로 옆 배출한 뒤 불량 전용 팔레트의 비중첩 바닥 슬롯에 격리한다. 푸셔가 작동하는 동안 안전 간격 때문에 상류가 잠시 정지할 수 있다. 불량 팔레트가 차면 별도 팔레트를 추가하고 손상 박스 위에는 쌓지 않는다. 처리 이력에서 검출·푸셔 대기·이송·완료를 확인하며 JSON에 형상/scan/status/격리위치를 기록한다. 정상박스 군집rank·안전제약·315mm/s·기존30개재현 프리셋(불량0%)은 그대로다.
검증: 관련20개테스트, 타입검사와배포빌드통과. 시드460000000의30개·발생률25%실험은 정상25개적재/불량5개격리(팔레트별7/7/6/5), 불량서브진입·집기0, 수량보존30. 브라우저240개·16%진행에서도 검출/푸셔이송/격리이력 및0%변경·재실행을확인했다. 이시연은 합성변형검출과운동학적분리모델이며 실제센서정확도·푸셔접촉력·파손후강도판정이아니다.
